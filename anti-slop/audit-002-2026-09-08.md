# Anti-slop audit 002: struktur folder

Tanggal: 2026-09-08  
Ruang lingkup: struktur folder, batas source dan runtime, dokumentasi struktur,
artefak QA, serta jalur verifikasi proyek Helpdesk IT Support.  
Mode: AFTER. Audit ini read-only terhadap source; hanya laporan audit yang dibuat.

## Ringkasan

Struktur utama proyek sudah memiliki pembagian yang masuk akal antara kode PHP,
asset antarmuka, database, storage runtime, dan upload. Namun delivery gate belum
lulus untuk struktur pemeliharaan. Ada artefak QA yang tidak lagi memiliki sumber,
stylesheet yang masih menyimpan banyak lapisan patch, dokumentasi struktur yang
tertinggal dari isi folder sebenarnya, serta migrasi database yang bertabrakan
dengan schema saat ini.

Status keseluruhan: FAIL untuk struktur delivery sampai temuan HIGH dan MEDIUM
yang dipilih ditangani serta diverifikasi ulang.

## Struktur yang ditemukan

```text
itsupport/
├── app/
│   ├── Http/       # handler form dan endpoint polling
│   ├── Storage/    # akses data MySQL
│   └── Support/    # helper, upload, rate limiter, CSV
├── assets/         # JavaScript, CSS, SVG, dan vendor Chart.js
├── database/       # schema utama dan satu migration SLA
├── storage/        # session dan rate-limit runtime
├── uploads/        # lampiran runtime
├── anti-slop/      # output visual QA lokal
├── index.php       # front controller dan template halaman
├── DESIGN.md       # arah visual dan kontrak UI
└── README.md       # setup dan dokumentasi proyek
```

## Temuan

### 1. Artefak visual QA tertinggal tanpa generator

- Prioritas: MEDIUM
- Rule: C-4, R-35
- Bukti: `anti-slop/visual-checks/` berisi 35 file dengan ukuran sekitar 2 MB.
  `report.json` hanya berisi array `pages`, `interactions`, dan `errors` yang
  kosong. Script pembuat screenshot sudah tidak ada, sementara folder ini hanya
  dikecualikan dari Git melalui `.gitignore:32`.
- Dampak: folder menjadi sampah lokal yang tidak dapat direproduksi dan bisa
  menyimpan data akun atau ticket dari screenshot. Kehadirannya juga membuat
  struktur `anti-slop/` tampak masih memiliki tool yang sebenarnya sudah dihapus.
- Perubahan: hapus output lokal yang sudah tidak dipakai, atau pindahkan seluruh
  hasil QA ke lokasi artefak terpisah dengan prosedur retensi dan redaksi data.

### 2. Stylesheet masih menjadi monolit dengan lapisan patch historis

- Prioritas: MEDIUM
- Rule: R-31, C-4
- Bukti: `assets/styles.css` memiliki 7.238 baris dan blok berurutan bernama
  `app.css`, `modern.css`, `modern-v2.css`, `fixes.css`, `admin-dashboard.css`,
  `business.css`, `theme-final.css`, berbagai blok phase, lalu kontrak ASCII,
  typography, dan notification di bagian akhir.
- Dampak: aturan visual tidak memiliki satu sumber kebenaran per komponen.
  Perubahan selector lama dapat kembali menimpa kontrak aktif, sehingga audit
  radius, font, warna, dan responsive harus membaca ribuan baris override.
- Perubahan: pecah stylesheet berdasarkan tanggung jawab yang nyata atau
  konsolidasikan menjadi urutan `tokens`, `base`, `layout`, `components`,
  `states`, `theme`, dan `responsive`. Hapus blok mati setelah bukti pemakaian
  selector dikumpulkan.

### 3. Peta struktur di README sudah tidak sesuai isi folder

- Prioritas: MEDIUM
- Rule: R-31, C-4, R-35
- Bukti: peta pada `README.md:96-125` tidak mencantumkan `app/env.php`,
  `app/Support/csv_export.php`, `app/Support/rate_limiter.php`,
  `assets/analytics.js`, `assets/ascii-field.svg`, `assets/vendor/`, dan
  `database/migration_sla.sql`. README juga masih mengarahkan setup ke
  `C:\xampp`, sedangkan workspace ini berada di instalasi Laragon.
- Dampak: developer baru dapat menjalankan instruksi yang salah atau tidak
  mengetahui file runtime dan asset yang benar-benar menjadi bagian aplikasi.
  Ini melemahkan bukti bahwa delivery dapat dijalankan ulang.
- Perubahan: jadikan peta folder dan instruksi setup sebagai dokumentasi yang
  diverifikasi dari struktur aktual. Pisahkan instruksi XAMPP dan Laragon hanya
  jika keduanya memang didukung.

### 4. Schema utama dan migration SLA tidak memiliki batas versi yang jelas

- Prioritas: MEDIUM
- Rule: C-4, R-31
- Bukti: `database/schema.sql:30` sudah membuat kolom `sla_deadline` dan
  `database/schema.sql:35` sudah membuat index `tickets_sla_index`. File
  `database/migration_sla.sql:5` dan `:27` mencoba menambahkan kolom serta index
  yang sama lagi.
- Dampak: menjalankan schema baru lalu migration SLA dapat gagal karena objek
  sudah ada. Sebaliknya, tidak ada penanda versi database atau prosedur migration
  yang memberi tahu file mana yang wajib dijalankan pada database lama.
- Perubahan: pilih satu strategi. Jadikan schema sebagai baseline baru dan
  migration sebagai migration historis yang terdokumentasi, atau buat runner
  migration berversi dengan pemeriksaan idempotensi.

### 5. Front controller masih memegang terlalu banyak template halaman

- Prioritas: LOW
- Rule: C-4, R-31
- Bukti: `index.php` berisi 875 baris, memuat login, shell aplikasi, detail
  ticket, form ticket baru, user management, analytics, dan beberapa blok
  `application/json` untuk JavaScript.
- Dampak: perubahan satu halaman harus dilakukan di file yang sama dengan
  routing, authentication boundary, dan response handling. Risiko regresi
  meningkat ketika UI bertambah, terutama karena CSS dan JavaScript juga masih
  berbentuk monolit.
- Perubahan: pertahankan `index.php` sebagai front controller tipis, lalu
  pindahkan view per halaman dan data serialization ke folder `app/Views/` atau
  `app/Presentation/`. Lakukan bertahap setelah batas tanggung jawab dipetakan.

### 6. Tidak ada manifest dependency atau jalur test yang dapat diulang

- Prioritas: HIGH
- Rule: R-35, C-4
- Bukti: tidak ditemukan `composer.json`, `package.json`, konfigurasi PHPUnit,
  Playwright, Cypress, Jest, atau manifest test/build lain. Chart.js disimpan
  langsung sebagai `assets/vendor/chart.umd.min.js`, meskipun versinya tertulis
  di header file.
- Dampak: verifikasi bergantung pada setup mesin lokal dan tidak punya command
  standar untuk lint, test, atau pemeriksaan interaksi. Setelah script visual QA
  dihapus, tidak ada cara resmi yang dapat diulang untuk membuktikan regresi UI.
- Perubahan: dokumentasikan minimal command lint dan smoke test yang benar-benar
  tersedia. Jika dependency vendor tetap dicheck-in, catat sumber, versi, dan
  lisensinya di `assets/vendor/README.md`; jika tool test ditambahkan, simpan
  konfigurasi dan fixture di lokasi yang jelas.

## Catatan hygiene kritis di luar pemetaan rule visual

`README.md:34-39` memuat kredensial akun admin development dalam plaintext.
Walaupun mungkin dimaksudkan untuk lokal, file tersebut berada di root proyek dan
tercatat sebagai dokumentasi. Kredensial harus dipindahkan ke setup lokal yang
tidak dibagikan dan akun tersebut harus dirotasi sebelum repository dibagikan
atau dideploy.

## Hal yang sudah benar

- `.env` tidak dilacak Git dan memiliki pasangan `.env.example`.
- Session, rate-limit state, dan upload runtime dikecualikan dari Git.
- `.htaccess` mematikan directory listing, memblokir direktori internal, dan
  `uploads/.htaccess` menolak eksekusi skrip di folder upload.
- Kode aplikasi sudah memiliki pemisahan awal `Http`, `Storage`, dan `Support`.
- Chart.js menyertakan versi 4.4.7 dan lisensi MIT di header vendornya.

## Batas audit

Worktree sedang memiliki perubahan lokal yang belum dikomit: beberapa file
source berubah, `DESIGN.md` dan `assets/ascii-field.svg` belum dilacak, serta dua
dokumen `SECURITY_UPDATES_PHASE*.md` tercatat terhapus. Karena itu audit ini
menilai struktur workspace saat ini, bukan baseline commit bersih.

Tidak ada file source, konfigurasi, atau runtime data yang diubah oleh audit ini.
